# Review

Use `harness/workflows/review.md` as the authoritative workflow.

Read the task, plan when present, relevant architecture docs, changed files, tests, and verification claims. When existing tests changed, verify the Test Change Report and produce a Test Integrity verdict. Report findings first by severity with file references, then open questions and residual risk.

Do not edit files unless explicitly requested. Do not commit, push, merge, reset, or clean.
