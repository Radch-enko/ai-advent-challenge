# Локальный анализ банковских выписок

CLI принимает один или несколько текстовых PDF-файлов поддерживаемого формата по счёту или карте, проверяет банковские итоги и создаёт JSON с операциями и показателями, а также Markdown-отчёт. Приложение запускается на ноутбуке. OpenAI помогает классифицировать операции и формулировать выводы; финансовые суммы и статистику считает локальный MCP-сервер через stdio с арифметикой `Decimal`.

## Установка и запуск

Требуется Python 3.11+. Из корня проекта:

```bash
python3 -m venv .venv
.venv/bin/pip install -e '.[test]'
cp .env.example .env
```

Заполните `OPENAI_API_KEY` в `.env`. Модель анализа задаётся через `OPENAI_MODEL` (по умолчанию `gpt-4.1`), модель эмбеддингов — через `OPENAI_EMBEDDING_MODEL` (по умолчанию `text-embedding-3-small`).

```bash
.venv/bin/finance-analyze statement-1.pdf statement-2.pdf --name october
```

Без API-ключа доступен демонстрационный режим: локальные правила вместо LLM и полнотекстовый поиск вместо семантического RAG.

```bash
.venv/bin/finance-analyze statement.pdf --offline --name demo
```

После чтения PDF CLI сохраняет `output/<имя>.preview.json`, показывает его путь и ждёт ввода **`да`**. Проверьте файл перед продолжением. Любой другой ответ, закрытие ввода или прерывание останавливают анализ. Подтверждение требуется и в `--offline`.

Результаты: `output/<имя>.json` и `output/<имя>.md`. Технические журналы: `logs/finance.log` и `logs/mcp.log`.

## Этапы пайплайна

| Этап | Что происходит | LLM |
| --- | --- | --- |
| 1. Парсинг и проверка | `parse_pdf` извлекает строки PDF по координатам колонок. Сохраняет дату совершения и обработки, для карты — также время. Сверяет суммы строк с итогами банка; для выписки по счёту дополнительно сверяет начальный и конечный баланс. `merge_operations` объединяет пересекающиеся выписки, сохраняя реальные повторные покупки. | Нет |
| 2. Маскирование и подтверждение | Локальный код создаёт очищенные выписки и операции. MCP сохраняет проверочный JSON. CLI ждёт подтверждения и затем повторно читает тот же файл. | Нет |
| 3. Индексация знаний | После подтверждения `index_knowledge` разбивает Markdown из `knowledge/` на фрагменты. В обычном режиме получает эмбеддинги OpenAI и кеширует их в SQLite; в `--offline` строит локальный индекс FTS5. | Модель эмбеддингов — только в обычном режиме; генеративная LLM не участвует |
| 4. Классификация | Явные переводы себе определяются локальным правилом. Для остальных операций LLM при необходимости сама формулирует запрос к `search_knowledge`, получает релевантные фрагменты и возвращает тип операции, категорию и признак неуверенности через Structured Outputs. | Да, кроме `--offline` |
| 5. Расчёты | `calculate_metrics` считает доходы, расходы, разницу, средние значения, категории, крупные покупки, динамику по неделям и месяцам, поведение в будни и выходные. Переводы между своими счетами отделяются от аналитических доходов и расходов. | Нет |
| 6. Отчёт | LLM может отдельно искать в базе знаний цели и правила пользователя и формулирует наблюдения и рекомендации по готовым показателям. Числовые разделы Markdown собираются локально; `write_report` сохраняет JSON и отчёт. | Да, кроме `--offline` |

Период покрытия берётся из заголовков выписок по **дате обработки**. Для анализа поведения по дням недели используется **дата совершения**. Поэтому операция может быть совершена до начала указанного периода и всё же попасть в него после обработки банком. Поддерживаются текстовые шаблоны выписки по счёту и карте за неделю и более длительный период. Другие форматы и сканы без текстового слоя пока не поддерживаются.

### Как работает RAG

`knowledge/` содержит ваши Markdown-заметки: финансовые цели, правила классификации и обстоятельства, которых нет в выписке. Индексация происходит после подтверждения preview JSON. Поиск не выполняется заранее по фиксированному списку запросов: во время классификации и подготовки отчёта модель сама формулирует запрос, когда ей нужен дополнительный контекст. `search_knowledge` строит эмбеддинг запроса, сравнивает его с локальными векторами по cosine similarity и возвращает ближайшие фрагменты с источниками. Число вызовов ограничено. Запросы агента и пути найденных заметок записываются в итоговый JSON. В `--offline` используется FTS5 и локальные правила без вызовов OpenAI.

## MCP-инструменты

Все инструменты ниже работают в локальном MCP-сервере через stdio. Python CLI вызывает их; сервер не размещается в сети.

| Инструмент | Назначение |
| --- | --- |
| `parse_pdf` | Прочитать один PDF, извлечь операции и проверить банковские итоги. |
| `merge_operations` | Объединить операции из нескольких выписок с учётом подтверждённых повторений. |
| `write_redaction_preview` | Сохранить очищенный JSON для просмотра и вернуть его контрольную сумму. |
| `read_redaction_preview` | После подтверждения повторно открыть JSON, проверить структуру и неизменность файла. |
| `index_knowledge` | Создать или обновить локальный индекс Markdown-заметок; кешировать эмбеддинги неизменённых фрагментов. |
| `search_knowledge` | Найти фрагменты по смысловой близости, либо через FTS5 в `--offline`. |
| `calculate_metrics` | Выполнить все денежные и календарные расчёты локально с `Decimal`. |
| `write_report` | Сохранить итоговые JSON и Markdown в `output/`. |

## Безопасность и границы маскирования

До подтверждения CLI **не отправляет запросы в OpenAI**. Парсинг, сверка, объединение, маскирование и сохранение preview JSON выполняются локально. В очищенной копии ФИО, отправитель и получатель, номера счетов и карт, исходные имена файлов и внутренние идентификаторы заменяются нейтральными значениями. Описание «Перевод между своими счетами. Перечисление средств на счет N …» сокращается до «Перевод между своими счетами». Для зарплаты, кешбэка и снятия наличных используются фиксированные безопасные метки. Если смысл свободного текста нельзя надёжно отделить от персональных данных, описание становится «Назначение скрыто», а категория остаётся неуверенной. Суммы, даты, направление операции и признак перевода себе сохраняются для расчётов.

Метки и категории конкретных продавцов можно хранить локально в `data/merchant_rules.json`; папка `data/` исключена из Git. Файл содержит список объектов с полями `marker` (фрагмент исходного описания), `label` (безопасное название для preview) и `category` (категория для `--offline` или `null`). Например: `[{"marker":"TEST_SHOP","label":"Покупка в магазине","category":"Продукты"}]`. Правила проверяйте вместе с preview: их метки могут попасть в запрос к модели после подтверждения. Без подходящего правила свободный текст покупки скрывается.

Preview JSON записывается с доступом только владельцу файла. После ввода `да` MCP-инструмент перечитывает его, проверяет схему и SHA-256 сохранённых байтов. Если файл был изменён, анализ прекращается: запустите CLI заново. Классификация, расчёты, RAG-запросы и отчёт используют **прочитанную после подтверждения очищенную копию**, а не исходные операции. Финальные JSON и Markdown также строятся из неё.

**Важная граница:** содержимое Markdown-файлов из `knowledge/` после подтверждения отправляется в OpenAI для построения эмбеддингов **без маскирования**. Найденные фрагменты могут передаваться генеративной модели. Не помещайте туда сведения, которые не хотите отправлять. Подтверждение preview JSON относится к данным выписки и не является проверкой содержимого базы знаний.

`.env`, PDF, `knowledge/`, индекс в `data/`, результаты в `output/` и журналы в `logs/` исключены через `.gitignore`. В технические логи записываются ошибки и HTTP-метаданные, но не ключи или тела запросов. Старые результаты в `output/`, созданные до добавления маскирования, автоматически не переписываются.

## Проверка и видеодемонстрация

```bash
.venv/bin/python -m pytest -q
```

Для видео покажите запуск CLI, просмотр `output/<имя>.preview.json`, подтверждение в терминале, затем итоговые JSON и Markdown. Перед публикацией видео проверьте также заметки `knowledge/` и суммы, которые не хотите раскрывать.
