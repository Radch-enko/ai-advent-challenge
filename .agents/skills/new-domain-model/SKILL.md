# New Domain Model

Прочитай `harness/policies/architecture.md` и `harness/policies/coding.md`. Размещай модель в
`src/copia/<feature>/domain/models`: один класс модели на файл. Не импортируй FastAPI, HTTP DTO или API package в
domain модель. Отделяй правила предметной области от сериализации и хранения; мапперы размещай отдельно от моделей.

Определи владельца модели до переноса между фичами. При миграции обновляй внутренние импорты на канонический путь
и проверяй отсутствие циклических импортов. Не оставляй файлы, состоящие только из повторных импортов и `__all__`.
Если модель содержит правила валидации или
переходов, проверь их сфокусированными тестами; затем запускай `./harness/scripts/check.sh`.
Если одну модель используют API, хранение и другие части фичи, оставляй одно определение в `domain/models`.
Не создавай копию модели в другом слое.
Если исходный модуль объединяет модели разных областей, переноси только модели выбранной фичи. Её API и data должны
импортировать новое определение напрямую; остальных потребителей переводи на тот же путь.
