# Политика архитектуры

- Размещай новый backend-код по функциональным областям в `src/copia/<feature>/`. Создавай внутри `api`, `application`,
  `domain`, `data`, `models` и `mappers` только при наличии соответствующего кода; не создавай пустые слои по шаблону.
- `api` содержит HTTP-модели и маршруты, `domain` — правила и предметные модели, `data` — хранение и интеграции.
  Модели храни в `models`, мапперы — в `mappers`, отдельно от обработчиков и сервисов.
- `application` используй для orchestration, связывающей domain, data и внешние runtime-компоненты (например,
  APScheduler), когда этот код не относится к HTTP и не является предметной моделью. Не импортируй `api` из этого слоя.
- В `tasks` размещай HTTP-маршруты и request-модели в `api`, правила формирования текста и planner-модели в `domain`,
  а worker с его стадиями и checkpoint orchestration в `application`. Точка сборки передаёт зависимости через
  runtime factory; не импортируй `service.py` из feature-пакета.
- В `mcp` размещай transport-маршруты, SSE и HTTP-модели в `api`, выполнение turn и сохранение runtime-состояния в
  `application`, разрешение доступных инструментов в `application`, а работу с MCP-соединениями и вызовами
  инструментов в `data`. Для потребителей из других фич используй общие функции точки сборки, не копируй алгоритм.
- В `scheduled_jobs` храни формирование периода, config и prompt в `domain/services`, постраничное чтение и запуск
  отчёта в `application`, HTTP-маршруты в `api`. Общие MCP-функции получай через точку сборки.
- В `agents/api` храни маршруты создания, отправки сообщения и удаления обычного агента и их HTTP-модели.
  Разнесённые в корневом API группы подключай в прежнем порядке; зависимости передавай из точки сборки через
  runtime factory, не импортируя `service.py` в feature-пакет.
- В `providers/api` храни provider-agnostic маршруты метаданных провайдеров и прямого completion, а также их
  HTTP-модели. Provider-specific HTTP остаётся в `providers/data`, очистка секретов — в `security/domain/services`;
  маршруты используют общий
  `LLMRouter`, полученный из точки сборки.
- В `agent_logs/api` храни маршрут чтения agent log, HTTP-модели и mapper из доменной записи в ответ. Другие
  фичи переиспользуют эти модели без копий контракта; хранилище и общий log lifecycle принадлежат `agent_logs`.
- В `sessions/api` размещай доступ к сессии, который преобразует ошибки в HTTP-ответы; состояние блокировки
  хранится в `sessions/application/models`. Все session-scoped маршруты используют один message/lifecycle lock
  из точки сборки, а подменяемые зависимости получают при вызове.
- `src/copia/service.py` остаётся точкой сборки FastAPI. Корневые `src/copia/api`, `src/copia/domain` и
  `src/copia/data` удалены; не создавай их повторно.
- Общие компоненты размещай по назначению в `storage`, `security` или `common`. Не выбирай одну предметную фичу
  владельцем общего правила только ради удаления корневого файла; не создавай импортные посредники.
- `src/copia/service.py` содержит не более 600 строк. Сборку компонентов отдельной фичи размещай в её `api`, а
  в `service.py` оставляй создание общих зависимостей и подключение маршрутов в установленном порядке.
- Фичевый сборщик объявляет собственную модель связей с именованными функциями получения зависимостей. Это позволяет
  использовать актуальные подменяемые объекты во время вызова, не импортируя корневой `service.py` в фичу.
- Подключай feature-роутеры в точке сборки; передавай нужные зависимости явно. Feature `api` не должен импортировать
  корневой `service.py`, чтобы не образовывать циклическую зависимость.
- Backend `domain`, `data` и `application` не должны зависеть от `api` ни в корне, ни внутри feature-папок. Не создавай циклических
  зависимостей между фичами; общий код выделяй только при подтверждённом совместном использовании.
- Если модель нужна нескольким частям одной фичи (например, API, хранению и выполнению инструментов), назначай ей
  одного владельца в `domain/models` этой фичи и импортируй из него; не создавай дублирующие определения классов.
- Provider-specific HTTP размещай в `src/copia/providers/data`; очистку credentials — в
  `src/copia/security/domain/services`.
- `client/src/domain` содержит frontend types, независимые от framework, и не должен зависеть от React, data или UI
  code.
- `client/src/data` может зависеть от frontend domain types, но не должен зависеть от UI components.
- `client/src/ui` может зависеть от domain types; `client/src/App.tsx` — composition layer клиента.
- Public provider-agnostic contracts не должны раскрывать adapter-specific payloads без явного API decision.
- Для каждого production change запускай `./harness/scripts/architecture-check.sh`.
