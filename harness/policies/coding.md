# Политика кодирования

- Поддерживай Python 3.11 или новее и размещай packages в `src/copia`.
- Используй Ruff для Python lint и formatting с ограничением длины строки 100 колонок.
- Используй strict checks TypeScript, ESLint и Prettier для React client.
- Предпочитай typed models, прямой control flow и небольшие public interfaces.
- Храни provider-specific behavior в adapters, а browser API calls — в `client/src/data`.
- Делай React effects явными и безопасными с точки зрения зависимостей.
- Добавляй dependencies только для конкретного текущего требования и документируй причину.
- Делай комментарии редкими и полезными; пиши их на русском языке.
- Размещай модели в `models` соответствующей фичи и слоя: один класс модели на файл, без
  обработчиков HTTP и бизнес-логики. Корневые `api`, `domain` и `data` не содержат моделей.
- Если модели разделяют валидируемые поля, размещай общий базовый класс в отдельном файле `models`; функции
  сериализации и подготовки prompt размещай в `domain/services`, чтобы не смешивать их с определением модели.
- Не создавай Python-файлы, состоящие только из повторных импортов, docstring и `__all__`. При переносе кода
  обновляй внутренние импорты и тестовые monkeypatch targets на модуль с реализацией; проверяй это в architecture
  check. `__init__.py` может определять осмысленный публичный API пакета; не считай его переходным shim без
  отдельного решения об изменении этого API.
- В точке сборки передавай функцию или метод компонента напрямую, если однострочный посредник только повторяет
  вызов. Сохраняй посредник, когда он адаптирует контракт или служит необходимой точкой поздней подмены зависимости.
- Не редактируй generated output, caches, virtual environments, `node_modules`, `dist`, `.run` или `*.egg-info`.
