## Продуктовая реализация в Copia

Пользователь обращается к агенту «Бухгалтер», например просит сравнить расходы за две недели и показать график. Агент ищет расходы через существующий `search_expenses`, передаёт две выборки в `compare_expense_periods`, затем передаёт результат сравнения в `save_expense_chart`. После одобрения каждого вызова Copia показывает его прогресс; сгенерированный PNG сохраняется отдельно от transcript, а LLM получает session-scoped URL и включает его в обычное Markdown-сообщение. По end-to-end подтверждению пользователя эта цепочка работает корректно.

Путь к функциям настройки MCP — экран MCP connections и настройки доступных MCP tools агента. UI содержит чекбоксы для allowlist, а подсказка рядом с ними предупреждает об отдельном approval на каждый вызов (`client/src/App.tsx:3123-3165`). Изображение отображается существующим markdown renderer как `<img>` с `loading="lazy"`; разрешены только безопасные URL (`client/src/App.tsx:3350-3388`). В режиме разработки `/api` проксируется на FastAPI (`client/vite.config.ts:5-13`).

## Техническая реализация

1. `search_expenses` обращается к Copia API и поддерживает фильтры и cursor pagination (`mcp-server/server.py:319-360`). Для полного набора записей модель должна продолжить пагинацию до `next_cursor=null`; описание инструмента отдельно это подчёркивает.
2. Модель передаёт две полные выборки в `compare_expense_periods`. MCP server вычисляет итоги, разницы, проценты и сравнения категорий с `Decimal`, подготавливая нормализованный `chart_data` для графика (`mcp-server/server.py:123-174,363-387`).
3. Модель передаёт полный результат сравнения в `save_expense_chart`. Matplotlib создаёт PNG image content в памяти (`mcp-server/server.py:390-437`).
4. `McpToolExecutor` извлекает PNG из MCP image content (`src/copia/mcp/data/mcp_tool_executor.py:50-83`). Tool loop передаёт артефакт publisher-у, сохраняет его до возврата tool result модели и передаёт `artifact_urls` следующему LLM-вызову (`src/copia/mcp/domain/services/mcp_tool_loop.py:155-167`, `src/copia/mcp/api/service_composition.py:162-171`).
5. Файл хранится по session-scoped ID; HTTP route выдаёт только существующий артефакт, иначе возвращает 404 (`src/copia/mcp/data/mcp_artifact_store.py:14-36`, `src/copia/mcp/api/artifact_routes.py:15-29`). Backend больше не добавляет Markdown-ссылку сам: модель должна вернуть точный URL из tool result согласно описанию инструмента.

Тестовые файлы содержат проверки десятичной арифметики, пустого периода, PNG content и artifact storage/route (`mcp-server/tests/test_expense_pipeline.py:24-72`, `tests/test_mcp_artifacts.py:37-104`). Это свидетельствует о наличии coverage, но тесты в рамках подготовки отчёта не запускались. В частности, текущий artifact test проверяет прежний `finalize` callback, а не новую передачу `artifact_urls` модели; интеграционный контракт цепочки по статическим тестам полностью не подтверждён.

## Сценарий демо

### Подготовка

- Убедиться, что в `~/.copia/files/finances.xlsx` есть лист `Expenses` с корректными расходами за два сравниваемых периода. Для демонстрации безопаснее использовать отдельную копию/тестовые данные; не выводить содержимое личного файла и секреты в запись.
- Настроить локальную конфигурацию Copia с ключом используемого LLM-провайдера, не показывая значение ключа на видео.
- Установить зависимости Finances MCP один раз по командам из `mcp-server/README.md:16-20`, если локальное окружение ещё не подготовлено.

### Запуск и запись

1. Запустить Copia API и web client из корня репозитория: `./scripts/restart-dev.sh`. По README API доступен на `http://127.0.0.1:8000`, UI — на `http://127.0.0.1:5173` (`README.md:16-30`). Для запуска нужны локально настроенный LLM provider и его секрет, но секрет не следует показывать.
2. Во втором терминале из `mcp-server/` запустить HTTP transport:

   ```bash
   COPIA_API_URL=http://127.0.0.1:8000 .venv/bin/copia-finances-mcp --transport streamable-http
   ```

   Это endpoint `http://127.0.0.1:8001/mcp` согласно `mcp-server/README.md:32-39`.
3. В UI открыть MCP connections и проверить/добавить локальное подключение `http://127.0.0.1:8001/mcp`; выполнить discovery/test connection, чтобы Copia увидела инструменты. Затем открыть настройки агента «Бухгалтер» и включить `search_expenses`, `compare_expense_periods`, `save_expense_chart`. Для демонстрации отключить `add_expense`.
4. Открыть чат агента «Бухгалтер» и попросить сравнить два конкретных соседних недельных диапазона, указав локальную временную зону и ожидая график. Даты выбрать по фактическим тестовым данным workbook; наличие этих данных заранее не подтверждено.
5. На каждом появившемся approval явно разрешить вызов. Ожидаемая последовательность: `search_expenses` для первого периода, `search_expenses` для второго, `compare_expense_periods`, `save_expense_chart`. При каждом шаге показать, что делает UI, а при необходимости раскрыть детали вызова/логи.
6. Проверить в финальном сообщении связный текст сравнения и встроенный график. Убедиться, что модель использовала URL из результата `save_expense_chart` в Markdown, а не имя `expense-comparison.png`; при необходимости открыть image URL в network/devtools и убедиться, что endpoint отвечает `image/png`.

### Checklist записи

- [ ] API, UI и Finances MCP server запущены; в кадре нет ключей и персональных финансовых данных.
- [ ] MCP connection прошёл discovery и доступны три инструмента цепочки.
- [ ] В запросе указаны точные диапазоны дат и часовой пояс, данные за оба периода есть в workbook.
- [ ] Показаны approval и фактический порядок четырёх tool calls.
- [ ] Видно, что сравнение вычислено инструментом, а не только текстом LLM.
- [ ] В финальном сообщении график действительно загружен и отображён.

Сценарий зависит от доступности настроенного LLM-провайдера, локального workbook с подходящими расходами и корректно зарегистрированного MCP connection. Ни один из этих runtime prerequisites в рамках статического анализа не проверялся.

## Итог проверки

В Copia реализованы три необходимые роли: получение расходов, детерминированный анализ и создание/сохранение PNG. Пользователь подтвердил, что end-to-end цепочка и отображение результата проверены и работают корректно. Оркестрация остаётся LLM-driven, а пользовательское подтверждение каждого MCP-вызова намеренно сохранено для финансовых операций; поэтому «автоматическое выполнение» здесь означает последовательное продолжение tool loop после разрешений, а не выполнение без участия пользователя.

В рамках подготовки отчёта проверки `pytest`, build и повторный запуск API/MCP server не выполнялись — использован статический режим; end-to-end результат учитывается как подтверждение пользователя, а не как независимый запуск в этом отчёте. `mcp-server/README.md:10-11` описывает прежнее поведение, где backend дописывает картинку сам; после последней корректировки это утверждение устарело и в рамках отчёта не исправлялось. Для демонстрации достаточно повторить уже работающий пользовательский сценарий и показать approvals, последовательность инструментов и итоговую картинку.
