# Задача

ID: DAY-29-JOURNAL-MCP
Status: approved
Title: Ежедневные заметки через локального MCP-агента

## Цель

Добавить профиль локального Ollama-агента, который ведёт ежедневные Markdown-заметки в базе знаний Copia через подтверждаемые MCP-вызовы и API основного backend.

## Контекст

- Заметки хранятся в `CopiaKnowledgeBase/Journal/YYYY-MM-DD.md`.
- Markdown-шаблон фиксирован:

  ```markdown
  # YYYY-MM-DD

  ## Главное за день

  ## Заметки

  ## Идеи и наблюдения

  ## Что сделать дальше

  - [ ]

  ## Благодарность или итог
  ```

- Агент может принять свободный рассказ либо провести короткий опрос по одному вопросу за раз.
- Пользователь подтвердил MCP-схему: агент предлагает изменения через MCP, MCP-сервер проксирует их в FastAPI backend, backend отвечает за проверку и файловое хранилище.
- Каждый MCP вызов с изменением проходит существующее одобрение Copia.
- Для поиска новой заметки через RAG пользователь вручную запускает переиндексацию.
- Текущий Docker bind mount `CopiaKnowledgeBase` доступен backend только для чтения. Для записи нужно отдельно подключить host-папку `CopiaKnowledgeBase/Journal` с правом записи, сохранив родительский mount read-only.
- Работа относится к одному локальному пользователю.

## Функциональные требования

- Добавить профиль ежедневного дневника с Ollama provider, моделью `qwen3:4b-instruct-2507-q4_K_M`, температурой `0.2`, лимитом ответа `768` токенов и системным промптом, сохраняющим сведения только со слов пользователя.
- Создать отдельный Journal MCP server с инструментами чтения и изменения дневника. Он делегирует файловые операции основному FastAPI backend через фиксированный API origin и не принимает путь к файлу от модели.
- Подключить инструменты к агенту через профиль `mcp_access`; изменения заметки должны отображаться как обычный MCP вызов и требовать подтверждения/отклонения пользователем.
- Добавить backend API и repository для заметки по ISO-дате. Имя файла и родительский каталог вычисляет backend внутри настроенного каталога `CopiaKnowledgeBase/Journal`.
- Поддержать чтение существующей дневной заметки и создание/изменение секций заметки структурированными операциями. Не давать модели редактировать заголовок даты или произвольный Markdown-шаблон.
- Сохранять неизменный порядок и написание заголовков из шаблона. Новые задачи добавлять незакрытыми (`- [ ]`); содержимое дневника не дополнять фактами, которых пользователь не сообщал.
- Обеспечить безопасную запись через временный файл и атомарную замену целевого файла; отклонять даты и операции, нарушающие контракт.
- Добавить узкое writable bind mount для `CopiaKnowledgeBase/Journal` в backend контейнер. Оставить mount родительской `CopiaKnowledgeBase` read-only.
- Сохранить ручной процесс переиндексации без автоматического запуска. Не добавлять напоминание о RAG после каждой записи; объяснять ручную переиндексацию, только если пользователь спрашивает о поиске заметки или RAG.
- Использовать модель, параметры и контекст `num_ctx=8192` для локального Ollama model variant через Modelfile; задать температурy и лимит в профиле. Поставку/скачивание весов выполняет пользователь локально.

## Нефункциональные требования

- MCP server остаётся тонким HTTP proxy; правила шаблона, выбор целевого каталога и файловая запись принадлежат backend.
- Docker MCP endpoint добавляется в существующий exact allowlist trusted endpoints, не разрешая остальные частные сети.
- Не добавлять authentication к новому локальному HTTP endpoint в рамках этой задачи.
- Не менять захват тел HTTP в OpenTelemetry; текущий capture policy принимается как известное ограничение.
- Не выполнять автоматическую переиндексацию после сохранения заметки.
- Не читать и не использовать реальные файлы пользовательской базы знаний при реализации и проверках.
- Не добавлять внешние runtime dependencies, если имеющиеся зависимости проекта покрывают задачу.

## Вне области задачи

- Планировщик, автоматическое начало опроса, календарные триггеры и автоматизация без открытой сессии.
- Автоматическая переиндексация, изменение UI индексации или создание нового UI экрана.
- Изменение общей политики MCP одобрений.
- Дополнительная защита прямого вызова HTTP endpoint.
- Изменение OpenTelemetry body capture, квантование или обучение модели.
- Редактирование произвольных файлов вне фиксированной папки Journal.

## Acceptance criteria

- [ ] Новый профиль виден как отдельный Ollama агент и ссылается только на Journal MCP connection/tools.
- [ ] Ollama model variant с `num_ctx=8192` создаётся из указанного Q4 instruct tag через Modelfile; README/task docs описывают команду создания без включения весов в Git.
- [ ] MCP discovery показывает инструменты чтения и изменения дневной заметки.
- [ ] Запрос на изменение в обычной сессии требует существующего одобрения пользователя; отклонение не меняет файл.
- [ ] MCP server вызывает backend endpoint и возвращает агенту результат операции без прямого доступа к файловой системе.
- [ ] Backend создаёт отсутствующий файл в `CopiaKnowledgeBase/Journal` по шаблону, либо читает/изменяет существующий файл, сохраняя формат и содержимое незатронутых разделов.
- [ ] Повторный запрос чтения не меняет файл; повторное применение одинаковой добавки не создаёт дубликатов.
- [ ] Backend отклоняет некорректную дату, неизвестную секцию/операцию, traversal, абсолютный путь и symlink escape; путь никогда не получается из аргумента модели.
- [ ] Запись использует атомарную замену; ошибка до замены сохраняет прежний файл.
- [ ] Docker backend видит `Journal` для чтения и записи, а остальные файлы базы знаний остаются смонтированы read-only.
- [ ] После успешного сохранения агент кратко подтверждает запись без напоминания о RAG; по вопросу пользователя объясняет, что для поиска через RAG нужна ручная переиндексация. Код не запускает индексатор автоматически.
- [ ] Проверки используют только временный каталог и вымышленные заметки; в Git нет данных из пользовательской базы знаний.

## Ограничения

- Папка базы знаний на host: `${HOME}/Desktop/CopiaKnowledgeBase`; папка дневника: `Journal`.
- В compose папка базы знаний уже примонтирована в `/data/documents/CopiaKnowledgeBase` read-only. Добавить отдельное writable-представление той же host-папки дневника, например `/data/journal`, и направить backend repository на него.
- Не выводить и не читать реальные `.env` values или contents базы знаний.
- Не менять пользовательские файлы вне согласованных source/config/test файлов и новой Journal MCP package.
- Один MCP write call — одна проверяемая пользовательская правка; отклонённый вызов не пишет данные.
- API origin MCP proxy фиксируется через `COPIA_API_URL`; не принимать полный URL или путь назначения от модели.
- Сохранить поддержку текущего Docker Finance MCP endpoint при добавлении отдельного Journal MCP endpoint.

## Риски

- UI MCP одобрение не аутентифицирует прямые HTTP вызовы нового endpoint; это принято для локального single-user MVP.
- При включённом OpenTelemetry HTTP body capture тексты дневника могут попадать в telemetry; это принято пользователем для текущего шага.
- Ручная переиндексация означает, что сохранённая заметка не сразу доступна через RAG.
- Локальный однопроцессный lock может не защищать запись при запуске нескольких backend workers; deployment assumption нужно проверить и ограничить либо применить подходящий межпроцессный механизм.
- Q4 tag требует наличия модели в Ollama у пользователя; тесты не зависят от локальной установки.

## Открытые вопросы

- Развёртывание Copia предполагает один backend process; проверить scripts/config и не вводить молчаливое multi-worker допущение.
- Операции редактирования: `append` и точные `replace/remove` по содержимому; для конфликтующих устаревших правок вернуть conflict без перезаписи.
- Инструмент чтения также использует текущий MCP approval lifecycle; отдельная политика read-only вызовов вне scope.
- При отсутствии конкретной даты используется текущая дата в `Asia/Omsk`; явная дата в речи пользователя имеет приоритет после валидации backend.
