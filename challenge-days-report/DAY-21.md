# День 21. Индексация документов

## Цель дня

Задание требует взять корпус документов достаточного объёма, построить чанки с метаданными, получить для них embeddings, сохранить локальный индекс и сравнить два способа разбиения. В Copia это оформлено как локальная библиотека документов; поиск и использование индекса агентами в этот день не входят.

Четыре статьи использовались как временный тестовый корпус для фактического запуска. По решению пользователя исходные статьи удалены из репозитория после анализа; JSONL, manifest и результат запуска остаются в Docker volume.

Источником этих статей была Wikipedia; перед повторной загрузкой текстов следует сверить текущую редакцию, историю и условия атрибуции на страницах источников.

## Продуктовая реализация в Copia

В навигации Copia добавлен экран «Документы» (`client/src/ui/ApplicationShell.tsx:80-87`, `client/src/App.tsx:504-508`). Пользователь кладёт статьи в настроенную папку, обновляет каталог, выбирает provider и модель, сохраняет настройки и запускает индексацию вручную. Экран показывает абсолютный путь к папке, число файлов и их размер. Папку можно задать через `COPIA_DOCUMENTS_PATH`; без override локальная конфигурация использует `COPIA_DATA_ROOT/documents`, по умолчанию `~/.copia/documents` (`src/copia/common/configuration.py:15-18,114-116`). В Docker Compose `COPIA_DATA_ROOT=/data`, поэтому каталог источников текущего контейнерного сценария — `/data/documents` (`compose.yaml:9-19`).

Настройки provider/model сохраняются локально и применяются к следующему запуску. UI получает список моделей настроенного provider, при этом ID модели можно ввести вручную; рядом показано предупреждение, что тексты чанков отправляются provider-у и обработка OpenAI может повлечь расходы (`DocumentsScreen.tsx:148-233`). Во время работы экран отображает этап и число обработанных файлов, после завершения — размерность вектора, объём корпуса, сводки двух стратегий и копируемый путь к папке запуска (`DocumentsScreen.tsx:235-337`). Полные чанки интерфейс не выводит: они доступны в JSONL-файлах.

## Техническая реализация

1. `DocumentLoader` читает локальные `.md`/`.txt` и формирует `source` из относительного пути, `title` — из имени файла без расширения (`src/copia/document_indexing/data/document_loader.py:21-52`). Структурная стратегия выделяет заголовки Markdown и абзацы; для TXT использует границы абзацев (`src/copia/document_indexing/domain/chunking/structure_aware.py:24-42,117-162`).
2. Общий provider-контракт включает `list_models`, `count_tokens`, `split_text` и `embed` (`src/copia/providers/domain/contracts/embedding_provider.py:8-24`). OpenAI adapter запрашивает каталог моделей и embeddings через `httpx`; модель по умолчанию — `text-embedding-3-small` (`src/copia/providers/data/openai_embedding_provider.py:23-30,47-76,105-148`). Токенизация для этого provider сделана через `tiktoken` (`:15-20,78-103`), но стратегии обращаются к ней через контракт provider.
3. API предоставляет чтение/сохранение настроек, список provider/model, запуск, состояние запуска и последнюю успешную сводку (`src/copia/document_indexing/api/routes.py:43-129`). Индексация выполняется фоновым worker; одновременно допускается один активный запуск (`src/copia/document_indexing/application/document_indexer.py:55-80`). При ошибке попытка получает состояние `failed`, а указатель `latest.json` обновляется только после сохранения обеих стратегий и manifest (`:155-184`).
4. Каждый запуск хранится отдельно: `document-index/runs/<run-id>/manifest.json`, `comparison.md`, `fixed-size.jsonl` и `structure-aware.jsonl`. JSONL-запись содержит текст, метаданные, число токенов и embedding; manifest — provider, модель, размерность, объём текста, источники и статистику стратегий (`src/copia/document_indexing/application/document_indexer.py:186-263,265-290`; `src/copia/document_indexing/api/service_composition.py:24-40`). Последний успешный запуск выбирается указателем `document-index/latest.json` (`src/copia/document_indexing/data/index_artifact_store.py:13-28,68-83`). В Docker данные находятся в сохраняемом volume `copia-data`, смонтированном в `/data` (`compose.yaml:9-19,43-44`).

### Фактический запуск

В существующем backend-контейнере найден успешный запуск `0868a4e72c14431a8cb749b1c7aeb93d`, указанный в `latest.json`. Его manifest датирован `2026-09-30 07:44 UTC`, выбран provider `openai`, модель `text-embedding-3-small`, размерность вектора — 1536. Артефакты включают manifest, comparison и обе JSONL-выгрузки.

| Стратегия | Чанков | Средний размер | Максимум | Лимит |
| --- | ---: | ---: | ---: | ---: |
| `fixed-size` | 50 | 492,08 токена | 512 | 512 |
| `structure-aware` | 99 | 225,91 токена | 679 | 680 |

В manifest записаны 4 источника, 110 058 байт, 109 971 символ и 21 660 токенов исходного текста. Суммарно по чанкам обе стратегии обработали 46 969 токенов (`24 604` для fixed-size и `22 365` для structure-aware); это выше объёма исходного текста из-за перекрытий и повторения контекста заголовков. Обе стратегии действительно получили embeddings, поэтому индексация двух вариантов отправляет содержимое чанков внешнему provider-у и влияет на расход.

Структурная стратегия сформировала почти вдвое больше чанков, а её средний размер меньше половины фиксированного. Это соответствует более мелким границам разделов и абзацев. При этом 19 из 99 структурных чанков короче 64 токенов, а 39 короче 128; у fixed-size таких чанков меньше одного порога: ноль короче 64 и один короче 128. Это заметный компромисс: структура сохраняется, но короткие абзацы дают дополнительные маленькие векторы и могут увеличить стоимость без доказанного улучшения поиска. Для текущего задания это не ошибка ограничения размера; качество retrieval этим запуском не измерялось.

Метаданные `title` в реальных записях — stem имени файла, например `copia-index-demo-game-design`, а не человекочитаемый H1 статьи. `section` структурных чанков хранит путь заголовков Markdown; у фиксированных чанков в качестве секции используется название документа. В начале по одному чанку каждой стратегии сохраняется Markdown frontmatter с атрибуцией. Для тестового корпуса это приемлемо, но перед библиотекой для регулярного использования стоит решить, нужно ли извлекать человекочитаемый заголовок из H1 и исключать frontmatter из индексируемого тела.

## Сценарий демо

### Подготовка

- Если Docker backend и его named volume с этим запуском сохранены, повторная индексация не нужна: откройте Copia и покажите последний успешный результат. В текущей Compose-конфигурации UI опубликован на `http://127.0.0.1:5173`, API — на `http://127.0.0.1:8000`; данные находятся в volume `copia-data` (`compose.yaml:16-19,32-44`).
- Для нового запуска положите собственные `.md` или `.txt` статьи в путь, показанный на экране; исходный тестовый корпус в репозитории не хранится. Локальный запуск по README: `./harness/scripts/check-dependencies.sh`, затем `cp .env.example .env` и `./scripts/restart-dev.sh`; задайте `OPENAI_API_KEY` в backend environment, не показывая его значение (`README.md:14-34`). Для Docker путь источников определяется `/data/documents`, если `COPIA_DOCUMENTS_PATH` не переопределён.
- Повторная индексация вызывает внешние OpenAI embeddings для обеих стратегий и может повлечь расходы. Не показывайте секреты API на записи.

### Запуск и запись

1. Откройте `http://127.0.0.1:5173` и выберите «Документы» в навигации.
2. Покажите путь папки, число файлов и размер корпуса. Для успешного запуска это 4 файла и 110 058 байт.
3. Покажите выбранные OpenAI и `text-embedding-3-small`, предупреждение об отправке чанков provider-у и о возможных расходах. Если демонстрируете новую индексацию, нажмите «Переиндексировать» и дождитесь завершения прогресса.
4. Сравните карточки: 50 фиксированных чанков против 99 структурных; средние размеры 492,08 и 225,91 токена. Обратите внимание, что максимумы обеих стратегий укладываются в настроенные лимиты.
5. Покажите объём в 21 660 токенов и размерность embedding 1536. Скопируйте путь к артефактам; при желании откройте `comparison.md`, manifest и JSONL из каталога запуска, чтобы показать текст, метаданные и вектор.
6. Завершите демонстрацию границей текущего этапа: это локальный индекс, агенты пока его не используют; поиск и RAG будут отдельной следующей задачей.

### Checklist записи

- [ ] На экране указан путь к каталогу и видны четыре статьи.
- [ ] Выбраны provider и embedding model; секреты не попали в кадр.
- [ ] Показаны этап/прогресс, если выполняется новый запуск.
- [ ] Показаны сравнение обеих стратегий, токенный объём и размерность вектора.
- [ ] Открыты локальные артефакты и несколько записей JSONL с метаданными.
- [ ] Сказано, что агенты пока не выполняют поиск по индексу.

## Итог проверки

Основное задание подтверждено фактическими артефактами успешной индексации: корпус требуемого объёма обработан, обе стратегии построены и эмбеддированы OpenAI, записи снабжены метаданными и сохранены в JSONL, manifest и сравнение сохранены отдельно. Экран Copia поддерживает ручной запуск и просмотр результата; индекс намеренно не подключён к агентам.

Практические ограничения результата: в этом запуске проверены только Markdown-файлы, а не TXT; `title` строится из имени файла; структурная стратегия создаёт много коротких чанков. Рекомендуемый следующий шаг — оценить короткие чанки на небольшом наборе запросов после появления retrieval, затем при необходимости подстроить правила объединения абзацев и извлечение заголовка.

В рамках подготовки отчёта артефакты последнего запуска были прочитаны из уже существующего backend-контейнера; новый запуск API, повторная индексация, тесты и сборка не выполнялись. В репозитории есть проверки document indexing (`tests/test_document_indexing.py`, `client/tests/document-indexing.test.ts`) и startup-конфигурации telemetry (`tests/test_fastapi_telemetry_configuration.py`), но их прохождение этим отчётом не подтверждается.
