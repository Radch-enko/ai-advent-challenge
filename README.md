# Code Assistance

Code Assistance — локальный CLI на Python, который помогает разбираться в документации и состоянии Git-репозитория. Он работает только на чтение: находит подходящие фрагменты документации и получает данные Git через встроенный MCP-сервер, работающий по stdio.

## Требования

- Python 3.11 или новее
- Git
- Ключ OpenAI API для индексации изменённой документации и ответов на вопросы

## Установка

Установите исходный код в редактируемом режиме через pipx, чтобы команда была доступна пользователю. В этом режиме CLI продолжит находить файл `.env` в корне проекта:

~~~sh
pipx install --editable /path/to/code-assistance
~~~

Для разработки:

~~~sh
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
~~~

После обновления исходного кода повторите установку в редактируемом режиме, чтобы создать исполняемый файл `code-assistance-git-mcp`. Чтобы запускать CLI из любого репозитория без активации виртуального окружения, добавьте каталог `bin` этого окружения в `PATH` либо установите пакет через pipx.

Команду можно запускать из любого каталога внутри Git-репозитория, который требуется изучить. Файлы `config.toml` и `.env` берутся из каталога с исходным кодом Code Assistance, поэтому этот каталог должен оставаться на месте. Для явного выбора репозитория используйте `--repo PATH`.

~~~sh
cd /path/to/your/repository/subdirectory
code-assistance
~~~

## Настройка OpenAI

Отредактируйте `config.toml` в корне Code Assistance, рядом с `pyproject.toml` и `.env`:

~~~sh
cd /path/to/code-assistance
${EDITOR:-vi} config.toml
~~~

Локальный `config.toml` исключён из Git: в нём можно хранить путь к MCP-серверу, зависящий от компьютера. Не помещайте туда ключ API. Для `OPENAI_API_KEY` используйте файл `.env` в корне Code Assistance.

Пример:

~~~toml
[openai]
base_url = "https://api.openai.com/v1"
chat_model = "gpt-5-mini"
embedding_model = "text-embedding-3-small"
# Необязательно. Если не указать, используется размерность модели по умолчанию.
# embedding_dimensions = 1024
timeout_seconds = 30

[index]
max_file_bytes = 1048576
top_k = 5
minimum_similarity = 0.25

[git_mcp]
# Исполняемый файл и аргументы задаются массивом; shell-команды строкой не принимаются.
command = ["/absolute/path/to/code-assistance/.venv/bin/code-assistance-git-mcp"]
tool_name = "get_current_branch"
timeout_seconds = 10
~~~

Поместите ключ в `.env` в корне Code Assistance, рядом с `pyproject.toml`:

~~~sh
OPENAI_API_KEY=your-api-key
~~~

Файл `.env` исключён через `.gitignore`. Если переменная `OPENAI_API_KEY` задана в окружении процесса, CLI использует её; иначе он читает только это значение из локального `.env`. CLI не выполняет `.env` как shell-скрипт и не печатает его содержимое. Не добавляйте файл в Git. Переменную окружения можно использовать для временного переопределения ключа.

В macOS и Linux ограничьте доступ к файлу своей учётной записью:

~~~sh
chmod 600 .env
~~~

По умолчанию чат-модель — `gpt-5-mini`, модель эмбеддингов — `text-embedding-3-small`. Их можно изменить в `config.toml`. Модель эмбеддингов и размерность полученных векторов сохраняются в локальном индексе. Смена чат-модели не перестраивает индекс.

## Контракт Git MCP

Встроенный stdio-сервер запускается автоматически при работе `/help`. Запускать его в отдельном терминале не требуется. Укажите в `command` путь к исполняемому файлу из вашей установки. CLI получает у MCP-сервера схемы доступных инструментов и передаёт их модели при каждом запросе. Для вызова выбранного моделью инструмента CLI самостоятельно добавляет абсолютный путь выбранного репозитория:

~~~json
{"repo_path": "/absolute/path/to/repository"}
~~~

Инструмент для ветки возвращает структурированный результат с полями `branch`, `detached` и `commit_sha`:

~~~json
{"branch": "main", "detached": false, "commit_sha": "0123456789abcdef"}
~~~

При detached HEAD поле `branch` равно `null`, а `detached` — `true`. Если в репозитории ещё нет коммитов, `commit_sha` может быть `null`. Сервер также предоставляет `get_status`, `get_recent_commits` и `get_diff`. Статус содержит пути и коды состояния Git; история — не более десяти SHA и заголовков коммитов; diff — ограниченные по объёму staged и unstaged изменения отслеживаемых файлов. Модель сама выбирает, какой из разрешённых инструментов нужен для ответа. CLI проверяет её выбор и аргументы, выполняет вызов через MCP и возвращает результат модели. Ошибка инструмента показывается явно.

Дочерний MCP-процесс получает ограниченный набор переменных окружения; `OPENAI_API_KEY` ему не передаётся.

## Использование

~~~text
$ code-assistance
OpenAI endpoint: https://api.openai.com/v1
Privacy notice: questions, relevant documentation excerpts, and selected Git data (including uncommitted diff) may be sent to OpenAI.
Documentation index ready: 4 file(s), 4 updated, 0 removed.
Enter /help <question> or /exit.
> /help Where is the project structure described?
The project structure is described in ... [README.md:L12-L18]
> /help What is the current branch?
Current branch: main [Git branch].
> /exit
Goodbye.
~~~

При запуске CLI сканирует только файлы `README*` в корне выбранного репозитория и Markdown-файлы в `docs/`. Он учитывает правила игнорирования Git и исключает файлы с чувствительными именами, каталоги зависимостей и временных данных, бинарные файлы, символические ссылки за пределы репозитория и файлы больше `max_file_bytes`. Выбранный endpoint OpenAI и предупреждение о передаче данных показываются до любого запроса к OpenAI, включая создание эмбеддингов.

Индекс SQLite хранится вне репозитория, в пользовательском каталоге данных платформы, в `code-assistance/indexes/`. Для каждого репозитория используется отдельная база данных; её имя основано на хеше абсолютного пути к корню репозитория. Хеши содержимого файлов позволяют обновлять только изменённую документацию и удалять записи об исчезнувших файлах.

Найденные фрагменты и вывод Git считаются недоверенными данными. Модель получает схемы разрешённых MCP-инструментов, сама решает, какой вызвать, и после вызова получает его результат. CLI разрешает только чтение Git и привязывает все вызовы к выбранному репозиторию. У модели нет доступа к произвольному shell, записи файлов или изменению Git. Ответы по документации содержат ссылки на пути и диапазоны строк, а ответы по Git — на пути или SHA, полученные через MCP. Если предоставленные источники не подтверждают ответ, CLI сообщает об этом.

## Проверки и ручной smoke test

Для запуска детерминированных тестов и проверок проекта:

~~~sh
./harness/scripts/check.sh
~~~

Ручной smoke test с настоящим OpenAI описан в `docs/SMOKE_TEST.md`. Для него нужен `OPENAI_API_KEY`. Обычные тесты используют поддельные реализации провайдера и не обращаются к OpenAI.

Первая версия работает только на чтение: она не редактирует файлы репозитория, не выполняет команды, выбранные моделью, и не поддерживает других LLM-провайдеров. Для эмбеддингов и ответов используется OpenAI. После стартового предупреждения вопросы о Git могут передавать провайдеру ограниченные данные статуса, заголовки коммитов и diff отслеживаемых файлов.
